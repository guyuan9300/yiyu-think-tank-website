# Page Design Skill

## 1. 设计原则
- 价值叙事优先：先时代意义，再工具机制，最后到功能细节。
- 软件本体价值优先：先讲清楚系统如何减少追问、整理、断档和凭感觉判断，再讲开源共建机制。
- 首页先回答“为什么这件事重要”，再回答“它怎么实现”。
- 功能不是主角，功能是价值证据。
- 现有功能要表达成“价值样板间”：它接住了什么过程、减少了什么人工、沉淀了什么经验、帮助谁做判断。
- 首页是价值解释页和入口页，不是完整工作台和后台操作页。
- 首页不承载全部筛选、全部 FAQ、全部功能细则。
- 每一屏只承担一个核心任务。
- 对外表达优先使用“组织场景、组织智慧、协作成本、社会资源”语言。

## 2. 视觉原则
- 优先用清晰分层，不靠卡片堆叠制造信息量。
- 轻量图形化优先：通过 CSS 与现有组件绘制结构图，不依赖外部重资产设计稿。
- 核心视觉优先级：
  - 组织智慧循环图
  - Before / After 对比
  - 分层/流程示意图
  - 少量精选卡片
- 同屏卡片数量控制在可扫读范围内。
- 动效克制，重点用于进入与导流反馈，不做炫技动画。
- 视觉气质保持可信、成熟、可持续维护。

## 3. 版式原则
- 页面最大宽度建议 `1180px`。
- 阅读型内容宽度控制在 `760px - 920px`。
- 大板块上下留白 `96px - 120px`。
- 每个板块必须有明确 `标题 + 副标题 + 单一任务`。
- 首页每个板块最多 2 个主要 CTA，避免选择过载。

## 4. 交互原则
- 首页只负责解释价值与导流。
- 首页必须提供角色分流入口：用户需要在 30 秒内识别“我是谁、我该点哪里”。 
- 复杂筛选放共建议题池页。
- 完整表单放提交页。
- 详细共建拆解放需求详情页。
- 首页需求池仅展示精选孵化条目。
- 价值段落后必须有行动承接，避免“读完才知道怎么参与”。
- 移动端优先保证两条路径：
  - 提交组织场景
  - 参与共建任务

## 5. 叙事主线模板
- 首页推荐主线：
  - 小组织每天做事
  - 过程留下来
  - AI 提炼
  - 经验复用
  - 管理判断更清楚
  - 开源共建扩展更多场景
- 价值解释主线：
  - AI 时代小组织价值
  - 协作与管理成本痛点
  - AI 如何降本增效
  - 组织智慧如何沉淀
  - 社会资源如何被释放
  - 开源共建如何参与
- 术语统一：
  - “需求池”对外展示为“共建议题池”
  - “功能模块”改为“价值样板间”
  - “提交需求”优先改为“提交组织场景”
